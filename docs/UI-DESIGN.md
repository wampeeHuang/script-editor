## 1. 诊断：为什么现在"粗糙且逻辑紊乱"

不是配色和圆角的问题，是**结构**的问题。四个具体病灶：

| # | 病灶 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | **三层盒子嵌套** | 段卡(border) → 单元(border-left) → 句行。每层都有边框或底色 | 眼睛看到的是**盒子**，不是句子。内容被容器噪音淹没 |
| 2 | **每行 6 个元素水平竞争** | `[3] [文本] [🔊][💬] [•] [2.4s]` | 文本是主角，却被 4 个元数据左右夹击；且图标语义重叠（🔊▶⟳ 都是"播放"），必须 hover 才知道区别 |
| 3 | **顶栏被"工作目录"占位** | 一个一次性配置项占着最贵的横向空间 | 每次看到它都在暗示"你还没配好"，制造焦虑 |
| 4 | **三页平级，但其中两个是低频** | 稿 / 声 / 轴 平级切换 | 95% 时间只待在「稿」，却要为低频操作付出页面切换成本；且预览常驻占 20% 宽度却信息量极低 |

**更深层的原因**：v3.0 的界面把**内部数据模型**（段/单元/句 三层）直接画给了用户。
「合成单元」是**实现概念**，不是用户的思维单位。用户想的是"我要改这句话"。

## 2. 信息架构：一主 + 两抽屉 + 常驻播放条

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏 40px   品牌 · 项目名          [待合成 42 字] 导出 投放 ⋯ │
├──────┬───────────────────────────────────────────────┬───────┤
│ rail │                                               │       │
│ 52px │  稿纸（唯一主界面 · max-width 760 居中）        │ 抽屉  │
│      │                                               │ 按需  │
│  稿  │  段落标题                                      │ 滑出  │
│  声  │  ┃ 句行                                       │       │
│  轴  │  ┃ 句行                                       │       │
├──────┴───────────────────────────────────────────────┴───────┤
│ 播放条 52px   ▶ ━━━━━●━━━━━━━ 00:04.2 / 00:11.4  朗读 试听 改这句 │
└──────────────────────────────────────────────────────────────┘
```

### 四条架构决策

**① 分组靠「连续色带 + 间距」，不再用盒子**
同一合成单元的行共享一条左侧竖色带，行与行紧贴；不同单元之间留 10px 呼吸。视觉上是**音频波形的韵律**，不是一个容器。
→ 用户不需要知道"单元"是什么，但能**感觉到**"这几句是一起念出来的"。

**② 播放是第二主角，收进常驻播放条**
v3.0 把 ▶⟳ 复制到每个单元、🔊 复制到每一行 —— 控件爆炸。
新方案：**所有播放动作收拢到底部播放条**，进度条上带**句级刻度**（每句一个可点击的小竖线）。
行内只留一个"待合成点"和时间。

**③ 声 / 轴 / 预览 / 设置 → 右侧抽屉**
它们是**低频决策**，不该占主界面。抽屉从右滑出 380～460px，**不离开稿纸**，关掉即回到写作。
rail 上的「声」「轴」是抽屉开关，打开时高亮。

**④ 顶栏收窄到 40px，工作目录移入设置**
顶栏只留：品牌 · 项目名 · **待合成胶囊** · 导出 · 投放 · 设置。
「待合成 N 字」是**常态成本信号** —— 取代 v3.0 的弹窗拦截。

## 3. 视觉系统

### 3.1 色彩语义重新分层（关键修正）

v3.0 的严重问题是**品牌绿同时承担了三种语义**：主按钮、clean 状态、单元边框。

**新规则：不给"正常状态"上色。** 绿色只属于"可以点的动作"。

| 层 | Token | 用途 | 用量 |
|---|---|---|---|
| **品牌层** | `var(--green)` / `var(--green-deep)` | 主按钮、当前 rail 项、播放进度 | 极少，只在动作上 |
| **文本 1** | `var(--ink)` 17px | 句文本（主角） | 大 |
| **文本 2** | `var(--ink-light)` 14px | 段标题、抽屉标题 | 中 |
| **文本 3** | `var(--ink-faint)` 11px | 行号、时间码、元数据 | 小且弱 |
| **分隔** | `rgba(var(--ink-rgb), .07)` | 密集列表的细线 | 极淡 |
| **卡片边** | `var(--line)` | 抽屉/卡片边框（品牌表达） | 少 |
| **状态：干净** | — | **无标记** | 0 |
| **状态：待合成** | `var(--status-warn)` | 一个 6px 圆点 + 色带满色 | 醒目但有节制 |
| **状态：播放中** | `var(--green-deep)` | 色带满色 + 行底 `rgba(var(--yellow-rgb),.35)` | 唯一强高亮 |
| **状态：失败** | `var(--status-error)` | 图标 + 行底极淡红 | 例外 |

### 3.2 字号层级（拉开差距）

v3.0 是 16/14/12，差距太小、没有层级。新方案三档拉开：

| 角色 | 字号 | 字重 | 行高 | 字体 |
|---|---|---|---|---|
| 句文本（主角） | **17px** | 400 | 1.7 | `--font-body` |
| 段标题 | 15px | 500 | 1.4 | `--font-head` |
| 抽屉标题 | 14px | 500 | 1.4 | `--font-body` |
| 行号 / 时间码 | 11px | 400 | 1 | `--font-code`，`tabular-nums` |
| 播放条时间 | 12px | 500 | 1 | `--font-code`，`tabular-nums` |

> 时间码用 `font-variant-numeric: tabular-nums` —— 数字跳动时不会左右抖。

### 3.3 间距（8 点体系）

| 位置 | 值 |
|---|---|
| 句行垂直 padding | 9px（点击区 ≥ 44px，满足触控标准） |
| 同一单元内行间距 | 0（贴紧，色带连续） |
| 单元之间 | 10px |
| 段之间 | 28px |
| 稿纸左右内边距 | 32px |
| 抽屉内边距 | 20px |
| 控件间距 | 8px / 12px |

## 4. 组件规范

### 4.1 句行（核心组件）

```
┃  3   就挂在我的小红书上，点开就能看。              •      5.8s
↑       ↑                                            ↑       ↑
色带    17px 文本，无边框       hover 才出现 ✦       待合成点  11px 等宽
3px     可点区域高 42px
```

| 状态 | 表现 |
|---|---|
| 默认 | 无背景；色带 40% 透明度；hover 时行底 `var(--cream)` |
| 聚焦（在编辑） | 色带 100%；行底 `var(--white)`；左侧 3px 品牌描边 |
| 播放中 | 色带 100% 品牌深色；行底淡黄；行号变成 `▶` |
| 待合成 | 色带琥珀色 100%；右侧 6px 圆点 |
| 指令展开 | 行下方 inline 展开输入框（不弹窗） |

**不做的事**：行内不放播放按钮（收进播放条）；不做 hover 才可见的时间（常显，但极弱）。

### 4.2 播放条

```
▶  ━━━━┃━━━┃━━━━●━━┃━━━━━  00:04.2 / 00:11.4  朗读  试听  改这句
       ↑句级刻度，可点击跳转
```

- 左侧按钮：有选中句时 = "从这句播"，否则 = "从头播"
- 进度条：已播部分品牌色；句级刻度是 1px 白色竖线
- 右侧三个文字按钮（不是图标）：`朗读`（0 成本）/ `试听`（当前后端）/ `改这句`
- **图标换成文字**：三个播放入口用图标永远分不清，用汉字一眼就懂

### 4.3 抽屉

统一规格：宽 380（声）/ 460（轴）/ 340（预览）/ 320（设置），从右滑入 180ms，带半透明遮罩（点击关闭）。
标题栏 44px：标题 + 关闭 ×。

## 5. 交互与键盘流

### 5.1 写作流（最重要的改进）

| 键 | 行为 |
|---|---|
| `Enter` | 在当前句下方新建一句，光标落入 |
| `Backspace`（句为空时） | 删除该句，光标回到上一句末尾 |
| `↑` `↓` | 上下移动句焦点 |
| `Space`（不在输入态） | 播放 / 暂停 |
| `←` `→` | 上一句 / 下一句 |
| `Ctrl+K` | 对当前句展开「改这句」指令框 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 |
| `Ctrl+S` | 立即保存 |
| `Esc` | 关抽屉 / 关弹窗 / 退出输入 |

> `Enter = 新起一句`是这个工具的核心心流 —— 写作时不需要碰鼠标。

### 5.2 播放跟随

播放时：当前句高亮 → 自动滚动居中 → 播放条进度推进。**用户能看见声音走到哪了。**

### 5.3 成本可见（替代弹窗）

- 顶栏胶囊：`待合成 42 字`，点击打开「声」抽屉
- 待合成时色带变琥珀色 —— **视觉本身就是成本信号**
- 只有点「更新配音」才出确认（读 N 单元 / M 字 / 预估费 / 耗时）——消费动作才需要确认

## 8. v3.2 精简（"less is more"，2026-09-16）

用户判定「信息太繁杂」。复查后确认：**问题不是画得多，是同一件事被说了 3~5 遍。**

| 事实 | 精简前 | 精简后 | 收敛到哪里 |
|---|---|---|---|
| 播放 | **5 处** | **1 处** | 底部播放条的 ▶（+ 一个来源标签） |
| 待合成状态 | **5 处** | **2 处** | 行左侧色带（就地）+ 顶栏胶囊（全局） |
| 时间与进度 | 4 处 | 2 处 | 行内时间码 + 播放条 |
| 全片时长 | 4 处 | 1 处 | 播放条时间码分母 |

原则：**每条事实只在一个地方说，且说在最靠近决策的地方。**

### 逐项删改

| 位置 | 删掉 | 理由 |
|---|---|---|
| 顶栏 | 产品名文字 | 用户知道自己开的是什么。留 20px 图标 |
| 顶栏 | 「已同步」胶囊（空态） | 把"什么都不用做"渲染成徽章 |
| 顶栏 | 「在线」文字 | 在线是常态；离线才需要用户行动 |
| 顶栏 | 自动保存提示 | 没有人会因为"已保存"改变行为 |
| 侧栏 | 「稿」按钮 | **它是个按钮却不打开任何东西** —— 把状态做成了控件。不亮 = 在稿纸 |
| 稿纸 footer | 撤销 / 重做 | 全局动作，移到顶栏图标（原来是稿纸末尾三个按钮） |
| 行内 | 行首 ▶、朗读图标、改这句图标、状态点 | 播放入口收成 1 个；待合成只看色带。**一行只剩 行号 / 文本 / 时间码** |
| 播放条 | 「朗读」「试听」两个按钮 | 合并进 ▶ 的智能选择（见下）；试听移到「声」的待合成清单 |
| 声抽屉 | 4 个指标 → 1 行「N 处待合成 · M 字」 | 费用留给确认窗；全片时长播放条已有 |
| 声抽屉 | 两句实现说明 hint | 标签上已写「免费/计费」「可自动/需手动」 |
| 预览 | 「导出只记字体名…」hint | 实现细节，不是用户要做的决定 |
| 设置 | 7 行快捷键表 | 收成一行；其余交给按钮 tooltip |

### 智能 ▶（新增的核心行为）

**播什么由系统决定，不让用户选。** 该单元已合成 → 播成品音频；改过还没合成 → 本机朗读即时出声（0 成本）。

播放条右侧只用一个标签说明当前是什么：`成品 / 本机朗读 / 试听`。

这条规则顺手消掉一个真实的坑：**原来改完一句按 ▶ 会听到上一版成品，且毫无提示。**

### 试听的位置

「试听」不是播放动作，是**生产动作**（会花钱合成）。它被移到了真正需要它的地方 ——
「声」抽屉的**待合成清单**里，每行一个。那里的心智是："我要决定这一单元值不值得重合成，先听一下"。

### 验证

`_runtime/ui_verify.js` 现已 60+ 断言，其中针对本轮精简的硬检查：

- 行内零按钮、刚好三个子元素、无状态点
- 播放条按钮 2 个（原 4 个）
- 侧栏 3 个入口、默认态全灭
- 顶栏无产品名 / 无「在线」文字 / 同步态胶囊不渲染
- 声抽屉 `#dw-voice .cell` 数量 = 0 且 `#voiceSum` 有一行汇总
- 清单里有 `[data-prev]` 就地试听按钮
- **待合成行色带确实变色**（`::before` 计算样式 dirty ≠ clean）——
  去掉状态点后这是唯一信号，不能只验类名
- 断言的**前置条件**：精简后 ⑦ 的撤销会让全部单元回到 clean，所以 ⑩ 必须自己制造一处改动才能验清单

## 9. v3.3：把"保存什么 / 存在哪 / 怎么进来"讲清楚（2026-09-16）

用户的连环提问暴露的其实是一件事：**工具没有把"工程"这个概念说出口。**

> "这个工作目录的载入是拿来干什么的？如果我能打开这个应用，不就说明已经载入了吗？"
> "为什么定义的是视频项目？该定义的不是它保存的目标位置吗？"

### 三个概念，各归其位

| 概念 | 是什么 | 界面上怎么出现 |
|---|---|---|
| **工程** | 一份文案 + 它的音频 + 时间轴，落在 `<目录>/narration/` | 「工程」抽屉里显示**实际路径**，不是空输入框 |
| **工程位置** | 工程的存放处 | 只读展示 + 「打开其它工程…」（点了才展开输入框） |
| **投放目标** | 成片项目根目录，`投放` 时写进它的 `_runtime/` | 未设置时**明说「未设置」**，不留一个像值的占位符 |

**「载入」这个按钮被删掉了** —— 它是个**无宾语的动词**，而且正常的载入（打开应用 → 自动读上次的工程）
早就发生了，摆在设置里只会让人以为"还没开始"。改成一个有宾语的动作：**打开其它工程**。

### 保存：不要按钮，但「还没存进去」必须看得见

保存一直是自动的（防抖 900ms 落盘 `project.json`）。问题在于**完全不可见**，于是用户会问"怎么保存"。

- ❌ 不加保存按钮（会诱导手动保存的焦虑，而自动保存已经保证不丢）
- ✅ 顶栏加状态：`● 未保存`（琥珀）→ `保存中…` → `已保存`（**1.6s 后自动淡出**）
- ✅ 离线时明确红字：`离线 · 改动不会保存` —— 这是原来真正危险的空档
- ✅ Ctrl+S = 立即保存（不再另弹 toast，状态指示本身就是反馈）

### 粘贴一整段

原来只能一行一行打字。现在在句行里粘贴时自动拆句，三级规则：

1. 有换行 → 按换行拆（最贴近「一行 = 一个逗号子句」的习惯）
2. 一整段无换行 → 按句末标点（`。！？…`）拆
3. 仍是长块（> 40 字）→ 按逗号类标点拆，别让它变成一个 60 字的合成单元

语义：**首行落进当前句（光标处），其余各起一句** —— 与普通编辑器一致。

### 再删两块 + 提示气泡补齐

- **删「服务」区块**：在线是常态；真出问题会在出问题的地方报错（后端卡片自带「不可用 + 原因」）。
- **删独立的快捷键表**：改挂到各元素悬停气泡（▶ / 撤销 / 重做 / 导出 / 投放 / 侧栏）。
  > 稿纸在 `overflow:auto` 容器里，CSS 气泡会被裁切 → 那里用原生 `title`。

### 顺带修掉：`data-tip` 一直是死属性

`data-tip` 写在标记里，但**一条样式都没有** —— 所有悬停提示从来没出现过。补齐后连踩两个坑：

1. 靠边的元素让气泡居中 → **一半跑到视口外被裁掉**（实拍：播放条 ▶ 的气泡左半截看不见）。
   修：顶栏与播放条一律贴边对齐（`right: 0` / `left: 0`），不居中。
2. 加了 `white-space: pre-wrap` 后气泡被**压成一字一行** —— 绝对定位伪元素宽度默认被

## 10. v3.4：导出 vs 投放 / 服务点 / 默认工程（2026-09-16）

### 「导出」和「投放」到底差在哪

它们都不"保存"（保存是自动的），区别在于**写出去的副本给谁看**：

| | 导出 | 投放到成片 |
|---|---|---|
| 写到哪 | **工程自己的** `exports/` | **视频项目**的 `_runtime/{script,tts,build}` |
| 写什么 | 6 个文件（含 `文案脚本.txt` 纯文本） | 5 个文件 + 拼接好的 `seg-000N.wav` |
| 会不会动成片 | **不会** —— 只是给你一份副本 | **会** —— 成片管线下一次构建就读它 |
| 什么时候用 | 想复制/发送/存档/给 agent 看 | 文案定了，要出片 |

按钮文案原来都太短，看不出区别。现在改成 **「导出」/「投放到成片」**，
提示语也写清了"副本 vs 进管线"。

### 服务状态：在线时整块不出现

原来顶栏右侧常亮一个青色小点。**一个常亮的点不承载任何信息** —— 在线是常态，
它唯一的副作用是让人以为可以点。现在在线时整块隐藏，只有**离线**（需要用户去启动服务）
时才浮出来（红点 + 「服务未启动」）。

### 默认工程：可配置，且有兜底

工具的 `--dir` / `default-project.txt` 现在能指定默认工程基目录（本机指向掼蛋视频项目的 `_runtime`）。

前端仍然优先用上次记住的目录，但加了一条兜底：**记住的目录里一个字的文案都没有时，
自动落到服务端的默认工程，并明确告知**（"上次的目录里没有工程，已打开默认工程"）。
理由：第一次用、换浏览器、清缓存都会走到这条路径，没有兜底就只能看到一个空的「未命名」，
用户会以为东西丢了。

### 投放目标：能从工程位置推出来

工程若落在 `<视频项目>/_runtime/` 下，投放目标天然就是它的上一层 —— 不用让人手填同一个路径。
现在未显式填写时自动推断，界面显示「自动：与工程同处」，并把推断结果**填进输入框的占位值**
（灰色字到底"会生效"还是"只是举例"，用户得能分辨）。

## 11. v3.5：自动保存的两处失守（2026-09-16）

用户第三次问「为什么没有保存」。前两次答的是"保存是自动的"，但真正该答的是：
**自动保存有两个洞，而我把它们当成"已经解决了"。**

### 保守（原有机制）

改字 → 防抖 900ms → `POST /api/project` → 落盘 `<工程>/project.json`。
顶栏显示 `● 未保存 → 保存中… → 已保存（1.6s 后淡出）`。

### 两个洞（实测确认）

| 洞 | 后果 |
|---|---|
| **没有关页兜底** | 敲完最后一个字，900ms 内关页 → 这次改动**丢** |
| **离线时直接 return** | 服务没起来时写的所有东西，**刷新即失**（原来只给了一句红字警告） |

### 补法：本机草稿当安全网

- 每次编辑额外在 **400ms** 时把工程写进 `localStorage`（`script_workbench_draft_v1`）
- **写进工程成功后清掉草稿** —— 所以正常情况下它转瞬即逝，不会变成常驻垃圾
- 关页 / 切走时 `pagehide` + `visibilitychange(hidden)` 用 `sendBeacon` 补发一次
- 下次打开时：把草稿和工程做一次**内容指纹比对**
  - 相同 → 说明只是"关页前那一次没来得及清草稿"，**静默清掉**，不打扰
  - 不同 → 弹窗问「恢复这份草稿 / 忽略」，绝不悄悄覆盖

> 指纹不能直接 `JSON.stringify` 比 —— 前端对象与服务端 `normalize_project` 后的键顺序不保证一致，
> 会误判成有差异。所以只比**段（id/标题/镜头数）+ 句（序号+文本）+ 标题**。

### 一条测试教训

第一次写这个断言时，我是"往 localStorage 塞一份草稿再刷新" —— 结果**测不出来**：
`pagehide` 上的 `flushSave()` 会用当前工程把注入的草稿覆盖掉。

**这说明安全网在正常工作，但测试手法错了。** 正确做法是复现真实场景：
**让"写进工程"失败**（拦掉 POST），再打字、再刷新 —— 这时草稿才是唯一的副本。

顺带踩到：Playwright 的 URL glob 会连查询串一起匹配，`"**/api/project"` 匹配不上
`/api/project?dir=...`，得用正则 `/\/api\/project/`。第一次跑的时候拦截没生效，
保存其实成功了，断言因此失败 —— 看着像代码有问题，其实是测试没拦住。

## 12. v3.6：编辑手感趋同「写一段话」+ 合成文本补标点（2026-09-16）

用户在真实使用中提了两条，都成立。

### 一、编辑手感（原来是"一堆独立单行框"）

| 动作 | 原来 | 现在 |
|---|---|---|
| 句中 `Enter` | 新起一个**空句**，后面的字还在原来那行 → 句子太长没法拆 | **在光标处断开**：前半留原句，后半成下一句，光标落到新句开头 |
| 行首 `Backspace` | 只有在**空行**时删掉整行；非空行没反应 | **并回上一句**，光标停在接缝上；跨段时提示「已并入上一段」 |
| 行尾 `Delete` | 无 | 把**下一句并进来** |
| `↑ ↓` | 一律跳到行尾 | **保持列位置**换行 |

> 一个直接推论（用户自己指出的）：**「＋ 加一句」按钮成了冗余** —— Enter 已经覆盖它的全部用途。
> 已删。只有「＋ 新增段落」保留，因为段是另一层（有停顿/换画面后果），不能靠 Enter 造。
>
> 代价：「新建段」原来靠那个按钮才能写第一句，现在改成**建段时自带一个空行**，
> 并给 `applyOps` 的删除段加了兜底（稿纸永远至少有一个可写行）。

### 二、行尾不写标点，送去合成时会补全

原来 `unit_text` 只是把单元内的行**直接拼接**（唯一处理是段尾逗号→句号）。实测后果：

```
显示:  我搓了一个网页版的小指南  /  就挂在我的小红书上，点开就能看。
合成:  我搓了一个网页版的小指南就挂在我的小红书上，点开就能看。     ← 中间什么标点都没有
```

TTS 会把「小指南」和「就挂」连读成一口气，听感上少一拍。而用户**经常为了让排版好看故意不打行尾逗号**。

**现在合成期补全（显示文本一个字都不动）：**

| 情况 | 处理 |
|---|---|
| 单元内相邻两行，上一行没有收尾符号 | 补「，」 |
| 上一行以 `~ ～` 收尾，或下一行以标点开头 | **不补**（否则成「小白~，」「百搭牌，，」） |
| 段尾是逗号类标点 | 换成「。」 |
| 段尾既无句末标点也无语气符号 | 补「。」 |
| 段尾是 `~ ～` | **不补**（「吧~」不该变成「吧~。」） |

**为什么显示文本不能跟着改**：用户不打逗号是**排版决定**，不是文案决定。
所以补全只发生在合成文本上 —— 这也正是 `unit_text`（合成文本）与 `sentences[].text`（显示文本）
分离的用意。补完的效果在「声」抽屉的**待合成清单**里能直接看到（那列显示的就是合成文本）。

### 三、在真实稿子上验证

用户当时已经在自己改稿（掼蛋工程从 30 句变成 40 句）。拿真实数据复核，抓到两个我没想到的边界：

1. `专门写给完全没打过的小白~` + `还有…` → 补成了 `小白~，` —— **`~` 得当成收尾符号**
2. 有一行用户手写了开头的「，」→ 补成了 `百搭牌，，两个7` —— **补之前要看下一行的第一个字**

两条都补了断言。

## 14. 事故复盘：一次误写吃掉了用户改过的稿子

**这是本项目最严重的一次事故，必须留档。**

### 经过

`api_smoke.py` 调 `/api/export` 时**没带 `dir=`**。而 `/api/export` 内部会
`ws.save_project(...)`，服务端的 `ws` 于是回落到**默认工程目录**（掼蛋视频项目的 `_runtime`）
—— 把测试用的 fixture 保存成了真实工程，**覆盖掉用户改到 40 句的稿子**。
同一时刻 `index.json` 与 `exports/` 也被覆盖。

### 为什么没被发现

- 服务端对"没带 `dir`"是**静默回落到默认目录**，不报错
- `/api/export`、`/api/publish` 明明是"读"，却各自偷偷 `save_project` —— 副作用不合理
- 测试脚本里只有两处带 `dir=`，其余都靠回落，而回落目标是**真实工程**

### 三处结构性修复

1. **写操作必须显式带 `dir=`，否则 400**（不报错变报错，回落在结构上不可能）
2. **`/api/export` 与 `/api/publish` 不再落盘 `project.json`** —— 保存是前端自动保存的职责，
   导出/投放只该读
3. **每次覆盖 `project.json` 前留一份历史**到 `narration/.history/`（环形 20 槽，不删文件，
   避开沙箱 unlink 拦截）—— 让"覆盖"永远可回退

回归断言：三个写端点不带 `dir` 必须 400（`api_smoke.py`）。

### 恢复

- 磁盘上**没有**用户那版的副本（`index.json`、`exports/` 同时被覆盖）
- 救命的是 **15:47:33 的一次「投放」**：它按设计把当时的 `build/` 备份到了
  `backup/20260916-154733/`，而写进去的是**用户浏览器内存里那份 40 句**（前端把它推了回来）
- 于是用 `build/文案脚本.md` 重建 → **逐字一致 24/25**（那 1 处是用户后来又修正的错别字，
  恢复出来的反而是更正后的版本）

### 教训（一句话）

**"没带参数就静默用默认值"，在写操作上等于埋了一颗地雷。**
读操作可以宽容，写操作必须显式。
