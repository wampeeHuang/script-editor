# 项目编辑页版式审查 · 2026-09-18

审查对象：http://127.0.0.1:8781/project/b160a2a69cbd4b29a77d3c4d404d4c2a

本轮只读审查，没有修改稿件、应用配置或页面实现，没有录音、合成、导出、恢复版本或提交 Agent 请求。打开页面可能按应用现有逻辑更新最近打开信息。通过浏览器检查了 1440×960 桌面、640×900 窄屏及 390×844 手机尺寸，并打开录音、配音、字幕预览、助手、版本面板和设置页。未验证麦克风权限、生成质量、版本恢复及真实导出链路；以下不得作为这些功能的验收结论。

## 总结

功能骨架值得保留：逐句文稿、章节顺序、录音和配音的对应范围、底部章节导航、版本恢复入口。现在的问题不是缺少更多控件，而是编辑页还沿用旧的紧凑外壳，列表页已形成的新布局没有统一进入编辑页。文字普遍偏小、正文随工具面板左右移动、预览空状态出现样式串扰、手机布局没有完成。

保持本地受管草稿箱、稳定项目 ID 和自动保存机制；不加入共享、所有者、云工作空间、旧视频投放管线或完整视频编辑器。布局统一不代表把列表页的 128px 页眉机械搬进编辑器；编辑器应优先保留阅读和写作面积。

## 实测问题与建议尺寸

以下建议是下一轮的设计目标，不是已经实现的状态。8px 为布局间距基数；字体和 1px 细框不必强制为 8 的倍数。

| 元素 | 1440px 桌面当前表现 | 建议 |
| --- | --- | --- |

| 保存状态 | 本次初次加载时为空 | 标题旁显示低强调的“已保存”或异常状态；失败必须可见 |

| 导航按钮 | 高 28px、字 12px、紧密排列 | 与已确认导航母版一致：32px 高、128px 色块宽、8px 间距 |
| 外框 | 顶部从 48px 开始，右侧与底部只留 8px | 桌面沿用顶部/右侧 32px 与导航色块右沿外 32px 的外壳合同；窄屏另用 16px |

## P0：先修功能性呈现

### 1. 预览空状态样式串扰

未选中句子时，“空行”状态标签变成高而窄的胶囊，把画布向下推，第一次打开像预览损坏。选中第一句后，字幕显示正常，画布实测为 306×544px（9:16）及 306×172.125px（16:9）；比例本身正确。

根因已由源码确认：`paintPreview()` 给标签设置 `lamp empty`；页面的通用 `.empty` 同时定义大块 padding、边框和圆角，`.lamp.empty` 只覆盖颜色，未隔离这些结构样式。应给状态标签使用独立的空态类，而不是继续叠加全局 `.empty` 修补。

未选句时显示“选择一句文案查看字幕”；选择了确实无文字的句子才叫“空行”。首开可定位第一句，但不能替用户自动播放。竖屏/横屏用切换控件一次呈现一种，避免两块画布纵向占满面板、把字幕设置挤到滚动区域深处。

### 2. 窄屏可用性

390px 视口中，侧栏仍宽 136px，正文工作区只剩 246px，实际文本列约 172px。截图可见长句后续文字没有完整显示，底部七个章节挤成不可读的小色块。需检查窗口尺寸改变后 textarea 是否重新执行自动增高；当前截图不能单凭这一现象断言所有初始手机加载都一样。

手机采用收起导航/菜单入口，正文占满主要宽度。工具面板采用可关闭的独立覆盖层，清楚提示正在查看哪个工具，而不是继续缩窄正文。章节条允许横向滚动，不把七章压成一排；播放器保留当前时间、播放和来源，次要内容折叠。手机输入正文建议 16px，主要触控区建议至少 44px。

## P1：统一外壳和编辑层级

### 3. 首页与编辑页的视觉系统

源码明确存在首页独立 `--home-*` 调色，而编辑页仍用旧绿色动作与黄绿色边框；相同 S Logo 在两页尺寸也不同。应抽出同一应用外壳和有效语义 token，不再让路由决定品牌配色。

保留用户已确认的背景/内容同色系、导航色块、32px 外边距、8px 圆角；外框一次负责圆角裁切，页眉、正文、面板和播放器不能互相盖角。Logo 沿用当前已确认的 SVG，不重画形象。页眉不增加“本地项目 · script-editor”“剧本工作台”等重复标题，也不新增顶部全局按钮。

### 4. 项目页眉

将掼蛋指南作为可编辑的项目标题，与正文左侧阅读轴线对齐。旁边显示简洁保存状态；第二行可放“7章 · 40句 · 472字 · 预估 1:45”。实际音频时长与预估时长必须分开表达。这里不需要大色块提醒或通用宣传副标题；只有未保存、素材缺失等可操作异常才显示提示。

### 5. 文稿与章节

正文是主要工作对象，提升到 16px/24px；章节标题建立 18px 层级，统计信息从目前 10px 提到 12px。章节顶部优先呈现标题，句数和预估时长放在标题旁或下方，而不是先显示一行小统计、再隔很远看到标题。

句号序号保持连续、弱化但可读；章节拖动柄和句序号不共用一套视觉符号。当前句/当前声音单元/待更新声音使用有解释的状态标记，避免无解释的浅黄竖线。句子输入聚焦遵守单细框规则，不叠加 outline 和 box-shadow，也不要把整行染成发光色块。

保持已确认的章节删除常显，但靠近章节头、使用低强调样式和足够点击区域，不成为每章最先看到的内容。保留逐句编辑及键盘操作，不重做成普通富文本。章节间距统一 32px；插入章节入口保留但降低重复占位，点击区仍需清晰。

### 6. 正文在打开面板时移动

1440px 视口中，不开面板时第一句起点约 x488；打开录音后约 x308，变化约 180px。不同面板宽度又产生不同偏移。这会打断阅读定位。

使用明确的正文/检查器分栏规则：保持阅读列左锚点稳定，优先消耗正文右侧留白；只有空间确实不足时缩小正文列，并在窄屏切换覆盖模式。不按每个工具的临时宽度重新居中全文。建议阅读列可用宽约 720–800px，留白有目的，不能为了填满屏幕无限加长行宽。

### 7. 底部播放器

保留章节导航和连续播放，但避免每章都用不同颜色占满视觉注意力。中性色作为默认，当前章节使用品牌强调；状态信息另用带文本说明的状态色。长章名截断并提供完整名称，不牺牲所有章节字号。

播放、当前时间/总时长、来源建立一条主操作轴；章节导航独立一行。统一时长格式，去掉 `01:45.7s` 混合写法。当前底部灰色分段条和章节条的职责要写清楚：没有真实项目音频时，只是预估文案导航，不伪装成已完成音频时间线或波形。

## P2：工具面板和文字减法

### 8. 录音

显示清楚“第几章 · 第几句到第几句”和所选全文，朗读稿至少 16px，不能只用小号摘要。开始/停止随状态切换一个主要操作；试听后再采用录音，导入音频为辅助操作。当前录音采用范围要与正文选择标记一致。没有录音时用简短引导，不把大半块空白填满无效说明。

### 9. 配音

“后端”改为“声音来源”；本机朗读与实际导出音频的区别必须明确。主操作说明更新范围；计费信息在发起前可见，单价未知时明确未知，不能猜费用。将技术单元名 `s1u1` 换为“第1章 · 第1组 / 第1–3句”，稳定 ID 留在详情。

当前“全部正常”描述的是语速/时间核对，另一处同时显示超出目标 45.7秒；两者不必然逻辑矛盾，但呈现容易让用户误解为整体通过。改为独立的“时间检查”和“目标时长”状态，重要目标偏差不要埋在待合成长表后。删除“删减文案即可”这种过度确定的说法，语速与剪辑节奏也会影响真实成品。

### 10. 助手

当前“交给 Agent”说明实际为请求落盘及复制，不能让按钮名称暗示已经启动常驻 Agent 或自动改稿。建议写“准备改稿请求”，按真实调度能力决定最终名称。选择整篇时，不只提示“当前选中第1句”，应明确“处理整篇 · 40句”；所选句信息与操作范围分开。

保留请求输入、范围、主操作、请求状态四部分；技术编号和将发送内容默认折叠。“你不用管编号”等口语解释可以删除。此次未发送请求，不能断言外部执行链路已经接通。

### 11. 版本

自动版本已有价值，保留。当前版本列表有大量同日近秒级记录，建议按日期分组，时间旁显示变化摘要或字数差，减少相同小卡片密集排列。当前版本标记、查看、恢复明确区分；点击查看不等于恢复，恢复必须保护现有稿件。这次没有执行任何恢复，功能行为未验收。

### 12. 设置与项目范围

设置实际跳转全局 `/settings`，编辑器工具则留在项目路由通过 `?panel=` 切换。路由做法可继续，但侧栏应让人清楚哪个是离开项目、哪个是打开工具；不要再拆新导航分区标题。返回项目必须保留编辑/滚动位置。

保持“草稿箱位置”和“默认导出位置”简约说明，与项目编辑器分离；项目内不重现旧的工程位置、投放目标、全局朗读诊断集合面板。未来音乐项目的原曲/歌词/图片应是项目素材，不把原曲与采用的旁白音频混为一项。本轮先修当前文稿编辑体验，不扩成 MV 编辑器。

## 推荐施工顺序与验收

1. 修独立空态样式和窄屏正文：首次打开预览不变形，未选句状态清楚；长句在加载、窗口缩放后都能完整显示。
2. 统一外壳、Logo、有效配色和页眉：桌面外边距一致，四角 8px，无盖角色块；标题/正文/辅助文字有明确层级。
3. 稳定正文与 384px 检查器：依次打开/关闭五个面板，正文不会因面板宽度不同来回跳。
4. 重排章节与播放器：七个章节仍可定位，预估与真实音频不混淆；主要操作易点，键盘聚焦只呈单细框。
5. 整理面板操作与范围文案：生成和录音先说明作用对象；助手不夸大执行能力；版本查看和恢复分离。

每步都复查 1440px、1024px、640px、390px，并检查实际长句、长标题及面板滚动。相同布局能力应复用组件，不通过继续追加全局 CSS 覆盖来制造表面一致。
