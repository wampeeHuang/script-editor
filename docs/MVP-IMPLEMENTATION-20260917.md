# 本地文案到旁白 MVP · 整改实施

范围：在现有 Python 服务和 Vivi 组件上完成保存、项目管理及交付闭环修补；没有改写框架，没有删除用户工程，没有调用付费合成或发布。

## 已实施

- 磁盘项目库：默认根目录扫描可重建目录索引；显式登记的外部工程仍留原处。浏览器记录仅用于缓存，旧记录首次登记有错误反馈。
- 工程严格打开：缺失、损坏、不支持的 schemaVersion 会失败；不会默默打开另一个工程或生成空白稿件。
- 保存保护：每工程进程内锁、递增 revision、原子 JSON 写入、旧版本冲突拒绝。前端项目写操作排队，响应不覆盖请求后继续写入的文字，本机草稿即时保存。
- 历史：20 个槽位按最老快照轮转，恢复前保留当前版本。旧工程身份/版本元数据迁移也留快照。
- ID 快照：`GET /api/project/snapshot?id=...` 返回版本与工程信息；隐藏/回收工程不解析。复制工程造成重复 ID 时拒绝自动替换原登记。
- 导航：原打开与最近项目合为「项目」；添加已有工程在项目页；MD/TXT 是「导入」新稿件，而不是打开多模态工程。
- 默认导出：文案 TXT/Markdown、完整旁白 WAV、明确选中的声音单元 WAV。声音要求 hash 与当前稿件一致且文件真实存在。完整导出不能漏段。每次交付单独目录，不覆盖旧交付，附 ID/revision/单元 hash 记录。
- 新 WAV 交付不插入估算空隙，与工程音频播放顺序一致；旧六件套 API 保持兼容，不将其估算字幕包装为精准字幕。PCM WAV 时长按采样帧计算。

## 验证入口

- `_runtime/mvp-tests/check.py`：16 项隔离模型、项目库、保存与 WAV 顺序/采样验证。临时工程自动清理，与用户目录分离。
- `_runtime/mvp-tests/serve.py`：独立 8796 服务和 fixture 项目库，不读取正式工程。
- `_runtime/mvp-tests/browser.js`：浏览器工程重开、清缓存新上下文、ID 路由、缺失目录、导出表单和历史恢复检查。使用 Playwright CLI 执行。
- `_runtime/mvp-tests/browser-race.js`：实际阻塞一次保存请求，并继续编辑，检查旧响应不覆盖新文字、新草稿保留、下一次保存正确落盘。
- 浏览器截图：`_runtime/mvp-tests/home.png`、`home-narrow.png`、`editor.png`、`live-home.png`。
- 8781 为正式入口；正式页检查不编辑用户稿件。恢复点 `_runtime/mvp-before-20260917/` 保存本轮修改前文件（包含原有未提交改动）。

本轮结果：模型/文件检查 16 项、浏览器流程 14 项、保存竞态 3 项通过。正式项目页浏览器 Console 为 0 errors / 0 warnings。900px 项目页检查通过，不代表全部手机尺寸和编辑器窄屏都已验收。使用合成 PCM 验证采用/导出，没有测物理麦克风声音质量或付费 TTS。详细结果见 `_runtime/mvp-tests/verification.json`。

## 当前边界

没有物理麦克风质量验收，没有真实外部用户测试，没有 ASR/词级对齐/文字剪辑媒体，也没有便携多模态项目包。接口为本机单用户合同，不是远程公开 API；revision 锁保护当前服务进程，不承诺多服务实例共同编辑同一个工程。

下一道发布门槛是用真实稿件、实际麦克风走一轮录制—重开—返工—导出，并请少量目标用户完成同一任务；不能以本轮自动化代替这两项。
