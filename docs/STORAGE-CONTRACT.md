# 本地项目的保存、导入与导出

2026-09-18。本文覆盖旧版“外部视频目录就是工作目录”的约定。

## 最基本的边界

项目是可继续编辑的工作单元，不是一个 JSON 文件。项目 ID 是永久身份，目录是可变地址，导出文件是交付副本。将三者混为一谈，会造成素材丢失、重复项目和历史成品被覆盖。

应用维护两种根位置：草稿箱负责项目，默认导出位置负责交付物。默认分别为 `D:/tools/script-editor/projects` 和 `D:/tools/script-editor/exports`。可以在设置中修改；修改草稿箱位置不等于搬迁已有项目。

## 项目内部归属

每个受管项目使用 `<草稿箱>/<projectId>/`。用户看到可修改的标题，机器用不变的 ID。

| 文件/目录 | 归属与职责 | 是否作为成品导出 |
| --- | --- | --- |
| `narration/project.json` | 文稿、身份、版本、素材角色和时间标记的权威数据 | 当前没有便携项目包导出 |
| `narration/assets/`、`materials.json` | 导入的原始资料副本，以及来源、大小、SHA-256 清单 | 不自动把所有附件当成品交付 |
| `narration/recordings/`、`units/`、`index.json` | 原始录音、采用/生成音频及其有效性索引 | 只显式导出当前选择且有效的旁白 |
| `narration/.history/`、`backup/` | 本地恢复资料 | 不混入成品 |
| `narration/preview/` | 可重建的试听缓存 | 不当作正式母带 |
| `narration/agent/` | 项目上下文请求 | 不当作交付内容 |
| `narration/exports/` | 旧兼容接口的历史交付根目录 | 每次仍生成独立子目录 |

迁移的历史项目允许保留已有目录。不能为了整齐移动文件而破坏内部引用。目录说明负责区分这些历史资料与当前权威数据；未识别的资料完整保留，不自动解析、采用或删除。

## 三个入口

**打开项目**：按项目 ID 从登记表找到目录，验证 `narration/project.json`。不把任意文件夹当成有效空项目。`projects/library.json` 是地址登记表，不是项目内容本身。其他工具通过 `GET /api/project/snapshot?id=<projectId>` 读取最新文稿快照，不靠固定绝对路径。

**导入资料**：文件选择、文件夹选择和拖入是三种取料方式，不是三种项目格式。可多次追加到同一待导入清单；确认后复制到一个新项目，校验后才登记，原文件不修改。资料用途（主音频、时间文本、附件）与格式分开。当前支持 MD/TXT、LRC/SRT、常用音频与图片，不支持任意多模态工程包、Word/PDF 或给已有项目追加资料；未确认清单刷新后不保留。整文件夹选择并不意味着能理解其中所有文件。

**导出成品**：先保存当前文稿，再生成本次选择的交付物。每次新建 `<导出根位置>/<YYYYMMDD-HHMMSS>-<8位随机标识>/`，不覆盖先前交付。面板的文案交付包含 TXT/MD，旁白交付为 WAV；附 `交付记录.json` 记录项目 ID、版本、格式。导出不移动项目、不改导入源、不自动投放旧视频管线。旧兼容导出接口也已改为独立子目录，但仍使用项目内旧交付根目录，不使用设置中的默认导出根位置。

## 《掼蛋指南》迁移

整个原 `_runtime` 纳入项目目录，项目 ID 不变：

`D:/tools/script-editor/projects/b160a2a69cbd4b29a77d3c4d404d4c2a`

迁移不重新生成文稿、音频和视频，不改变其内容。原位置只保留迁移标记，工作台访问它时明确报错，防止旧标签自动保存出第二份项目。项目列表与默认入口更新到新目录。外部旧脚本若硬编码原路径，不再视为受支持入口，须由其所属项目另行改用 ID 或新位置；本轮没有改动那些外部脚本。

恢复快照：`F:/_migration-snapshot/script-editor/20260918-guandan`。停服务后可恢复快照 runtime 与目录登记、默认入口；恢复前保留新位置的后续修改，不直接覆盖。

## 项目删除生命周期（2026-09-18）

移入回收站只修改登记状态，保留完整项目。彻底删除需要确认名称；仅允许删除当前受管根目录的直接项目子目录，拒绝外部目录、链接和正在生成配音的项目。删除覆盖整个 ID 目录（包括文稿、素材与历史文件），不再只删除 `narration/`。

`projects/deleted-projects.json` 是应用级删除保护记录，按完整旧路径登记 ID 和删除时间，不是项目内容或回收站项目。记录在实际删除前落盘，阻止旧标签或已持有的工作目录对象重新创建项目；应用重启后仍有效。删除遇到文件占用等错误会明确失败并保留保护记录，不假装完成；部分失败需检查残留后处理，不自动恢复成项目。

两个历史的仅含 `.deleted-script.json` 的目录已移除；标记备份在 `archive/legacy-runtime/deleted-markers-backup-20260918/`，其保护记录已迁入应用级文件。

## 尚未实现，不包装为现成能力

- 新项目的外部资料复制和当前内容导出已经实现；便携的完整项目包“导出—导入”尚未实现。
- 既有项目继续追加资料、统一素材浏览与每次导出历史列表尚未实现。
- 整体迁移与成品导出不是同一功能，前者要迁移全部依赖，后者只交付明确选择的产物。
- 本机快照帮助回滚，但不是持续备份服务，也不保证磁盘损坏后无损恢复。
